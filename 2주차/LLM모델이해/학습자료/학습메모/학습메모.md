# LLM 모델 이해 및 활용

---

## 소프트웨어 개발 방식의 진화 과정

**규칙을 직접 작성**→ **데이터를 통해 규칙을 학습** → **자연어로 목표와 역할을 지시** → **AI가 코드 생성·추론·행동 수행**

## 단계별 요약

* **Software 1.0:** 사람이 모든 논리와 규칙을 프로그래밍 언어로 구현
* **Software 2.0:** 사람이 데이터와 모델 구조를 제공하고, 신경망이 규칙을 학습
* **Software 3.0:** 사람이 목표와 역할을 자연어로 정의하고, AI Agent가 필요한 코드와 행동을 생성
  * AI agent : 목표를 바탕으로 도구를 사용하고 행동하는 인공지능
  * Agentic AI : 자율적으로 일을 판단하고 필요한 agent를 설계하는 인공지능

## 전통적인 개발 vs AI 소프트웨어

| 구분        | 전통적 개발                                   | AI 소프트웨어 개발                                    |
| ----------- | --------------------------------------------- | ----------------------------------------------------- |
| 핵심 개념   | 사람이 규칙을 코드로 직접 작성                | 데이터와 목표를 바탕으로 모델이 판단·행동            |
| 개발 목적   | 컴퓨터에 정해진 일을 시키는 것                | 컴퓨터가 스스로 처리할 수 있도록 준비하는 것          |
| 주요 산출물 | 함수, 코드, 프로그램                          | 학습된 모델, 프롬프트, 컨텍스트                       |
| 개발 방식   | 명시적인 규칙과 로직 구현                     | 데이터 학습 및 자연어 명령 활용                       |
| 입력 요소   | 요구사항, 알고리즘, 소스 코드                 | 목표·역할, 데이터, 프롬프트                          |
| 동작 특성   | 결정론적: 같은 입력에 예측 가능한 결과        | 통계적·확률적: 상황에 따라 결과가 달라질 수 있음     |
| 주요 도구   | 프로그래밍 언어, 라이브러리, 프레임워크       | ML·DL·LLM, 데이터셋, AI Agent                       |
| 개발자 역할 | 코드 작성자, 로직 구현자                      | 문제 정의자, 데이터 설계자, 사고·행동 설계자         |
| 구현 절차   | 필요한 함수를 찾아 조합하여 애플리케이션 완성 | 목표와 데이터를 제공하고 모델의 결과를 평가·개선     |
| 지능 구현   | 사람이 모든 판단 규칙을 코드화                | 모델이 데이터에서 규칙을 학습하거나 스스로 추론       |
| 인터페이스  | 코드와 API                                    | 자연어와 프롬프트                                     |
| 장점        | 동작을 예측하고 원인을 추적하기 쉬움          | 복잡한 판단 처리와 개발 자동화·속도 향상             |
| 한계        | 모든 규칙을 사람이 정의해야 함                | 편향, 환각, 불확실성 및 설명하기 어려운 오류 가능     |
| 품질관리    | 테스트를 통해 코드와 함수 검증                | 데이터·프롬프트·모델 출력에 대한 지속적인 평가 필요 |
| 발전 단계   | Software 1.0                                  | Software 2.0에서 Software 3.0으로 발전                |

> 핵심적으로 **전통적 개발은 함수를 만들고, AI 소프트웨어 개발은 모델을 만든다**고 요약할 수 있다.
> 향후, Software 3.0에서는 여기에 더해 사람이 목표와 역할을 정의하면 AI가 코드 생성, 추론, 행동까지 수행하게 된다.

## 새로운 AI 시대의 도래 **트랜스포머**

문장 속 단어들이 **어떤 관계**가 있는지를 **한 번에** 파악해서 정보를 처리하는 **딥러닝** 아키텍처이다.
맥락 정보를 기가막히게 이하할 수 있도록 만들어짐 **HOW?**

> 기존 LSTM처럼 단기 기억 장치를 사용하더라도 응답을 잘 못했지만 Attention!!(문장을 생성하려는 시점에 전체를 다 보고 **중요한 것**만 **집중**하기)을 통해 **맥락을 읽는다.**

### 기존 RNN, LSTM과 트랜스포머의 차이

| RNN/LSTM                     | Transformer                          |
| ---------------------------- | ------------------------------------ |
| 토큰을 순서대로 처리         | 여러 토큰을 병렬로 처리              |
| 긴 문장의 앞부분을 잊기 쉬움 | 멀리 떨어진 토큰 관계도 직접 계산    |
| 병렬 학습이 어려움           | GPU 병렬 학습에 유리                 |
| 순서가 구조에 포함됨         | 위치 인코딩을 별도로 사용            |
| 긴 문장에서 학습이 느림      | 상대적으로 효율적인 대규모 학습 가능 |

### 트랜스포머 플로우

**입력 문장**
**→ 토큰화
→ 임베딩
→ 위치 정보 추가
→ Self-Attention
→ Feed Forward Network
→ 다음 토큰 또는 결과 출력**

![1784769554414](image/학습메모/1784769554414.png)

| 구성 요소                | 역할                                             |
| ------------------------ | ------------------------------------------------ |
| 토큰화                   | 문장을 모델이 처리할 작은 단위로 분할            |
| 임베딩                   | 토큰을 의미를 담은 숫자 벡터로 변환              |
| 위치 인코딩              | 각 토큰의 순서와 위치 정보 추가                  |
| **Self-Attention** | **문장 내 모든 토큰의 관계와 중요도 계산** |
| Multi-Head Attention     | 여러 관점에서 토큰 관계를 동시에 분석            |
| Feed Forward Network     | Attention 결과를 변환하여 특징 추출              |
| 잔차 연결·정규화        | 학습을 안정적으로 만들고 정보 손실 방지          |

> ### Self-Attention
>
> 하나의 문장 안에서 단어 간 관계를 계산합니다.
>
>> 철수는 사과를 먹었다. 그는 배가 고팠다.
>>
>
> `그`를 처리할 때 같은 입력 문장에 있는 `철수`에 높은 중요도를 부여합니다.
>
> ```
> 입력 문장
>  ├─ Query ─┐
>  ├─ Key ───┼→ Attention 계산
>  └─ Value ─┘
> ```
>
> 즉, Q·K·V가 모두 동일한 입력에서 만들어집니다.
>
> ### 일반 Attention—Cross-Attention
>
> 서로 다른 두 데이터 사이의 관계를 계산합니다.
>
> 영어 번역을 생성할 때:
>
> ```
> Query     ← 디코더의 현재 상태
> Key/Value ← 인코더가 이해한 한국어 문장
> ```
>
> 디코더가 `school`을 생성할 때 입력 문장의 `학교`에 집중하는 방식입니다.

| 구분            | Attention                                        | Self-Attention                           |
| --------------- | ------------------------------------------------ | ---------------------------------------- |
| 의미            | 한 데이터가 다른 데이터의 중요도를 계산          | 같은 데이터 내부 요소끼리 중요도를 계산  |
| Query 출처      | 현재 처리 중인 데이터                            | 동일한 입력                              |
| Key·Value 출처 | 다른 입력 또는 표현                              | 동일한 입력                              |
| 주요 목적       | 입력과 출력 사이의 관계 연결                     | 입력 내부의 문맥과 관계 파악             |
| 예시            | 번역문의 단어가 원문의 어떤 단어를 참고할지 결정 | 문장 내 단어들이 서로 어떤 관계인지 파악 |



Query     ← 디코더의 현재 상태
Key/Value ← 인코더가 이해한 한국어 문장


### 인코더와 디코더

- 문장 으미의미를 파악하고 (인코더) -> 컴퓨터가 이해할 수 있도록 바꾸기 (디코더)

| 구분      | 인코더(Encoder)         | 디코더(Decoder)                         |
| --------- | ----------------------- | --------------------------------------- |
| 핵심 역할 | 입력의 의미와 문맥 이해 | 문맥을 바탕으로 결과 생성               |
| 처리 방식 | 입력 전체를 동시에 참고 | 이전에 생성된 토큰을 참고해 순차 생성   |
| Attention | Self-Attention          | Masked Self-Attention + Cross-Attention |
| 대표 모델 | BERT                    | GPT                                     |
| 주요 활용 | 분류, 검색, 감정 분석   | 대화, 글쓰기, 코드 생성                 |

### 기존 모델과 현대 LLM 비교

- 실습 0, 1-1을 통해 LSTM을 통해 문장 생성을 보자

| **구분**                | **기존 모델 (RNN / LSTM)**                   | **현대 LLM (Transformer)**                     |
| ----------------------------- | -------------------------------------------------- | ---------------------------------------------------- |
| **처리 방식**           | **순차 처리**(단어를 하나씩 순서대로)        | **병렬 처리**(문장 전체를 한 번에)             |
| **문맥 이해 방식**      | 이전 정보를 순차적으로 전달 (뒤로 갈수록 잊어버림) | **Self-Attention**(모든 단어 간의 관계도 계산) |
| **장문 처리 능력**      | 문장이 길어지면 성능 저하 (장기 의존성 한계)       | 길고 복잡한 문맥도 뛰어난 이해력 유지                |
| **학습 속도 및 확장성** | 병렬 처리가 불가능해 학습 속도 느림                | 병렬 처리 가능 ➔ 초거대 모델(LLM) 구축 가능         |
