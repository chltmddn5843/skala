# PartFlow 요구사항·화면설계서

기준일: 2026-09-08
성격: SKALA 9주차 제출용 설계 초안. 실제 제조 규정이 아닌 교육용 가상 정책이다.

## 1. 목표와 범위

금속 브래킷 `BR-A`의 작업지시, LOT 생산실적, 구멍 지름 검사 결과를 연결한다. 품질 이상이 발견되면 같은 품목·설비에서 지정 시간대에 생산된 LOT을 추가 확인 후보로 조회하고, 선택한 생산·검사 메모를 AI가 요약한다.

구현 범위는 한 공장, 한 생산 공정, LOT당 최종 전수검사 1회다. 자재·공정 라우팅, 재작업, 출하, ERP·PLC 연동은 제외한다.

## 2. 액터

| 액터 | 할 수 있는 일 |
| --- | --- |
| 생산관리자 | 작업지시 생성·조회·종료, 전체 LOT 조회 |
| 작업자 | 작업지시 시작, LOT 생산실적 등록 |
| 품질담당자 | 측정값 등록, 관련 LOT 조회, 메모 요약 생성 |

## 3. 작업지시·LOT 규칙

- 작업지시는 `무엇을 얼마나 언제까지 생산할지`를 나타내는 계획이다.
- LOT은 작업지시를 실행해 같은 품목·설비 조건에서 생산한 실제 묶음이다.
- 작업지시 1개에서 LOT 여러 개를 만들 수 있고, LOT 1개는 작업지시 1개에만 속한다.
- 작업지시 상태는 `PLANNED → IN_PROGRESS → CLOSED` 순서다.
- 작업자가 시작하고 생산관리자가 종료한다. 목표수량 미달 종료에는 사유가 필요하다.
- 종료된 작업지시에는 LOT을 추가할 수 없다. LOT 생산수량 합은 목표수량을 넘을 수 없다.
- LOT은 품목, 설비, 생산 시작·종료 시각, 수량, 작업자, 생산 메모, 적용 검사규격을 보존한다.
- 예시: `WO-0908-01 / BR-A / 목표 10개`에서 `LOT-A 5개`, `LOT-B 5개`를 생산한다.

## 4. 품질 규칙

- 가상 검사 항목은 브래킷 구멍 지름이며 목표 `10.00 mm`, 허용범위 `9.90~10.10 mm`다.
- LOT 생산수량만큼 측정값을 한 번에 등록한다. LOT당 확정 검사 1개만 허용한다.
- 서버가 LOT에 연결된 규격 버전으로 각 값을 `PASS` 또는 `FAIL`로 판정한다. 경계값은 적합이다.
- 관련 LOT 조건은 기준 LOT과 같은 품목·설비이면서 조사구간 `[from, to)`와 생산구간이 겹치는 경우다.
- 시간 중첩 조건은 `started_at < to AND ended_at > from`이다. 기준 LOT은 제외하고 검사대기 LOT을 먼저 보여준다.
- 관련 LOT 결과는 추가 확인 후보이며 불량·영향 범위 확정이 아니다.
- AI는 선택된 생산·검사 메모에서 사실, 미확인 사항, 다음 확인 질문만 요약한다. 판정과 관련 LOT 선정은 일반 로직이 담당한다.

## 5. 기능 요구사항

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| F01 | 역할별 로그인 | 사전 등록 계정으로 역할을 구분한다. |
| F02 | 작업지시 관리 | 관리자가 품목·목표수량·납기를 입력하고 목록/상세를 조회한다. |
| F03 | 작업지시 상태 변경 | 작업자가 시작하고 관리자가 종료하며 잘못된 전이를 거절한다. |
| F04 | LOT 실적 등록 | 진행 중 지시에 설비·시간·수량·메모를 등록한다. |
| F05 | 치수검사 등록 | 품질담당자가 생산수량만큼 값을 입력하면 서버가 판정한다. |
| F06 | LOT 통합 조회 | 생산조건, 적용규격, 측정값, 판정과 메모를 한 화면에서 본다. |
| F07 | 관련 LOT 조회 | 기간을 입력해 같은 품목·설비의 시간 중첩 LOT과 선정 근거를 본다. |
| F08 | AI 메모 요약 | 선택 기록을 요약하고 원기록과 함께 표시한다. AI 실패가 원기록을 바꾸지 않는다. |

## 6. 화면 구조와 이동

`S01 로그인 → S02 현황 → S03 작업지시 목록 → S04 작업지시 상세·LOT 등록 → S05 LOT 상세 → S06 검사 등록`

| 화면 | 사용자 행동 | 주요 표시·검증 | 연결 API |
| --- | --- | --- | --- |
| S01 로그인 | 계정·비밀번호 입력 | 실패 메시지, 역할별 첫 화면 | `POST /api/auth/login` |
| S02 현황 | 작업지시/LOT 필터, 상세 이동 | 진행 지시 수, 검사대기 LOT, 부적합 측정 수 | `GET /api/dashboard`, `GET /api/lots` |
| S03 작업지시 목록 | 생성, 상태 필터, 상세 이동 | 번호·품목·목표/생산·납기·상태 | `GET/POST /api/work-orders` |
| S04 작업지시 상세 | 시작·종료, LOT 등록 | 목표 초과·종료 상태·미달 종료 사유 검증 | `GET /api/work-orders/{id}`, 상태/LOT API |
| S05 LOT 상세 | 검사 이동, 조사기간 입력, AI 요약 | 생산·규격·검사·관련 LOT·선정 근거·메모 | LOT 상세/관련 LOT/요약 API |
| S06 검사 등록 | 측정값 행 입력·확정 | 생산수량과 행 수 일치, 서버 판정 결과 | `POST /api/lots/{id}/inspection` |

## 7. 대표 시나리오

1. 관리자가 BR-A 10개 작업지시를 만든다.
2. 작업자가 지시를 시작하고 M1 설비에서 LOT-A 5개, LOT-B 5개를 등록한다.
3. 품질담당자가 LOT-A에 `9.90, 10.00, 10.10, 9.89, 10.11`을 입력한다.
4. 서버는 3개 PASS, 2개 FAIL로 판정한다.
5. 품질담당자가 조사기간을 지정해 같은 BR-A·M1의 관련 LOT 후보를 확인한다.
6. 선택한 생산·검사 메모를 AI가 요약한다.

실패 사례는 중복 작업지시/LOT 번호, 목표 초과 생산, 종료 지시의 LOT 등록, 생산수량과 측정값 개수 불일치, 중복 검사, 권한 위반이다.

## 8. 와이어프레임 사용법

`PartFlow_와이어프레임.html`을 브라우저로 열어 좌측 메뉴로 여섯 화면을 전환한다. 화면 내용 확정 뒤 Figma로 옮겨 자동 레이아웃과 컴포넌트를 적용한다.
