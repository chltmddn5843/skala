## MES를 선택하는 이유

MES는 제조 현장의 생산 실행을 추적·기록·관리하는 시스템이다. 생산지시, 실적, 품질, 추적성이 연결되므로 CRUD뿐 아니라 상태 전이와 데이터 관계를 학습하기 좋다. MES 전체의 학습과 이번 제출 범위는 구분한다.

외부 보충 근거: [SAP MES 설명](https://www.sap.com/sea/products/scm/execution-mes/what-is-mes.html), [Siemens 제조 추적성 설명](https://blogs.sw.siemens.com/opcenter/manufacturing-traceability-how-your-mes-adds-product-value/). 아래 규모·업종·기능은 어시스턴트의 교육용 제안이며 실제 공장의 확정 업무 규칙이 아니다.

## 추천: 소형 부품 생산·품질 이력 관리 + AI 검사 메모 요약

한 줄 정의: 작업자가 생산 LOT별 실적을 기록하고, 품질 담당자가 검사 결과를 등록하면, 관리자가 생산·불량 현황과 AI 요약을 함께 조회하는 웹 서비스.

가정: 가상의 소형 부품 제조 현장, 한 공장·한 라인·한 품목군·최종 검사 중심. LOT은 이 프로젝트에서 함께 생산·관리하는 제품 묶음이다. 공장별 LOT 정의는 달라질 수 있다.

대표 시나리오(가상): 작업지시 100개 → LOT-A 생산완료 100개 → 100개 전수검사, 적합 96개·부적합 4개 → 불량 유형과 작업 메모 저장 → AI가 관찰 사실·미확인 사항·추가 확인 항목 요약 → 담당자가 검토.

이 경우 부적합품률은 4/100=4%이다. 샘플검사일 때는 검사 수량을 분모로 별도 표기해야 하며 이를 전체 생산 불량률로 단정하지 않는다. 부적합 제품 수와 결함 건수는 다르다. 한 제품에 결함이 여러 개면 결함 건수 합계가 부적합 제품 수를 넘을 수 있다.

| 액터 | 역할 | 주요 화면 |
| --- | --- | --- |
| 생산관리자 | 작업지시 등록, 생산·품질 현황 확인 | 작업지시 목록/등록, 현황 |
| 작업자 | 지시 조회, 시작·완료 및 생산실적 입력 | 작업지시 상세/실적 입력 |
| 품질 담당자 | LOT 검사 등록, 이력 확인, AI 요약 검토 | 검사 입력, LOT 상세/요약 |
| 외부 AI 서비스 | 제공된 기록에서 요약 반환 | 사용자 화면 없이 서버와 연동 |

공통 로그인과 역할별 진입을 포함하고, 각 화면의 상세/입력은 패널로 합칠 수 있다. 화면 수를 맞추기 위해 필요한 흐름을 생략하지 않는다.

## 핵심 설계와 학습 포인트

| 영역 | 최소 제안 | 학습 포인트 |
| --- | --- | --- |
| 작업지시 | 품목·목표수량·예정일·대기/진행/완료 | 지시와 실제 생산실적의 차이, 유효한 상태 전이 |
| 생산기록 | LOT 번호·지시·완료수량·작업자·시각 | LOT과 작업지시의 차이, 누가 언제 기록했는지 |
| 품질검사 | LOT·검사수량·부적합수량·유형·메모·검사자 | 생산 완료와 품질검사 완료 구분, 수량 검증 |
| 이력 조회 | LOT 기준 지시·실적·검사·요약 연결 | 생산 LOT 내부 추적성. 원자재부터 출하까지의 전체 추적성은 아님 |
| AI 요약 | 검사 기록을 읽어 사실·특이사항·확인 질문 작성 | 계산과 생성의 역할 분리, 근거 기록 참조 |

초기 엔터티 후보: 사용자, 품목, 작업지시, 생산 LOT, 검사 기록, AI 요약. 검사 유형·측정 항목은 확정 요구에 맞춰 추가한다. 품목 1:N 작업지시, 작업지시 1:N 생산 LOT, LOT 1:N 검사 기록으로 검토한다. 화면/API 정의 후 최종 DBML을 작성한다.

초기에는 전수검사·재검사 없음으로 범위를 한정하면 수량 의미가 명확하다. 재검사를 포함한다면 검사 회차와 최신 유효 판정을 구분해 이중 집계를 막아야 한다. 원본 기록과 정정 이력 정책도 상세 설계에서 정한다.

## AI 역할

계산된 검사수량·부적합수량·유형별 집계와 작업 메모를 입력으로 요약 초안을 생성한다. 결과에는 근거 검사 ID, 관찰 사실, 미확인 사항, 추가 확인 항목을 구분한다. AI 출력과 담당자 검토 결과는 구분해 저장한다.

AI 필요성 제안: 현장 메모가 자유문장으로 흩어져 있으면 검토자가 읽고 정리하는 시간이 든다. LLM은 여러 기록의 표현을 정리해 인수인계용 초안을 만들 수 있다. 담당자는 근거 기록을 확인하며 수정하므로 요약 편의성을 얻고 원기록과 판단을 보존한다.

수량·비율 계산은 서버/SQL이 담당한다. AI가 불량 원인을 확정하거나 합불 판정·출하 승인을 자동 결정하는 기능은 넣지 않는다. AI 실패 시에도 생산·검사 기록 저장과 조회는 동작하도록 설계한다. 사용할 기록이 가상이면 화면과 발표에 가상 데이터임을 명시한다.
