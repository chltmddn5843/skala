# PartFlow 백엔드 설계 워크시트

설계 전에 [MES 설계 학습 노트](MES_설계_학습노트.md)의 1~6절을 읽는다. 전부 암기할 필요 없이 각 컬럼이 계획·실적·기준정보 중 무엇인지 설명할 수 있으면 된다.

> 최신 기획 우선순위: 기본 MES 범위를 가볍게 유지하고 [페인포인트 기획](MES_페인포인트_기획.md)에서 핵심 문제를 먼저 선택한다. 아래 상세 설계 작업은 그 선택에 맞춰 조정하며, 백엔드 설계는 사용자가 맡는다.

## 지금 할 첫 과제 — LOT 데이터와 조회 규칙 (20분)

첨부된 엘리베이터 고장 데이터 분석을 반영한 권장 컬럼과 조회 규칙은 [데이터 컬럼 설계](MES_데이터컬럼_설계.md)에 정리했다. 사용자는 그 구조를 복사하기보다 아래 사례가 실제로 표현되는지 확인하고 작업지시·LOT 관계를 자기 말로 설명한다.

전체 워크시트를 한 번에 작성하지 않는다. 아래 가상 사례에 필요한 데이터와 규칙을 한국어로 먼저 작성한다. 기존 검사 API 과제는 이 과제 이후 진행한다.

같은 날짜에 같은 품목 BR-A를 생산한 기록:

| LOT | 설비 | 생산 시작~종료 | 검사 상태 |
| --- | --- | --- | --- |
| A | M1 | 09:00~09:30 | 치수 부적합 발견 |
| B | M1 | 09:30~10:00 | 검사대기 |
| C | M2 | 09:00~09:30 | 검사대기 |
| D | M1 | 13:00~13:30 | 검사대기 |

A를 조사하며 M1의 09:00~10:00 생산 범위를 조회한다. 기본 의도는 기준 A를 별도로 보여주고 B를 추가 확인 후보로 제시하는 것이다. B를 불량으로 확정하지 않는다.

1. LOT에 어떤 정보를 저장해야 하는가? 한글 항목명을 적기.
   - 내 답:
2. 작업지시와 LOT은 어떤 관계인가? 지시 10개를 LOT A 5개·B 5개로 생산하는 경우를 생각하기.
   - 내 답:
3. 관련 LOT 조회는 어떤 조건인가? 권장안은 기준 LOT 제외 + 같은 품목 + 같은 설비 + 지정 시간과 생산시간이 겹치는 LOT이다. 검사 상태는 모두 표시하고 검사대기를 우선한다. 이 규칙에서 바꾸고 싶은 부분을 적기.
   - 내 답:

설계 힌트: 생산 시작·종료 시각을 저장하고 조회 범위와 시간이 겹치는 LOT을 찾는 방식을 추천한다. 시작만 범위 안에 있는지 보면 08:50~09:10처럼 일부 겹치는 LOT을 빠뜨린다. 정확히 10:00에 시작하는 LOT의 포함 여부도 정해야 한다. 시간 구간은 시작 포함·끝 제외로 두는 것이 기본 제안이며 아직 사용자 확정은 아니다. 같은 설비라도 품목이 다를 때 포함할지, 검사 적합 LOT도 보여줄지는 자동으로 가정하지 않는다.

다음 순서: 사용자 답→어시스턴트 데이터 관계 리뷰→검사 데이터·API 설계→코드와 화면 연결. 이 과제는 이해 확인이며 정답 형식의 SQL·코드 제출을 요구하지 않는다.

## 이번 학습 소재

자동차·가전용 브래킷의 **구멍 지름 치수 검사**. 브래킷 사례가 업계에서 가장 흔하다고 단정하는 것이 아니라, 규격·측정값·판정·LOT 추적을 함께 익히기 위한 대표 학습 사례다.

가상 품목 BR-A의 검사 규격: 목표 10.00 mm, 하한 9.90 mm, 상한 10.10 mm. 하한·상한을 포함해 이 범위 안이면 이 검사 항목에 적합하다. 값은 모두 학습용이며 실제 도면·고객 규격이 아니다. 입력은 소수점 둘째 자리까지로 정하고, 더 많은 자릿수는 몰래 반올림하지 않고 오류로 안내하는 기본안을 사용한다.

BR-A 한 품목으로 대표 시나리오를 먼저 완성한다. 추가 품목 BR-B는 별도 규격을 설정한 후 확장한다. 실제 측정기 연결은 없으며 수동 입력한 가상 데이터다. 측정 불확도·측정기 적합성·교정·실제 출하 판정까지 검증한 시스템이 아니다.

### 수량을 작게 잡아 끝까지 실행하기

데모 LOT 5개를 전수검사하며 번호 1~5는 해당 LOT 안의 검사 대상 식별번호다. 전 세계 고유 제품 일련번호로 취급하지 않는다.

| 대상 번호 | 측정값(mm) | 기대 결과 |
| --- | --- | --- |
| 1 | 9.90 | 적합: 하한과 같음 |
| 2 | 10.00 | 적합 |
| 3 | 10.10 | 적합: 상한과 같음 |
| 4 | 9.89 | 부적합: 하한 미만 |
| 5 | 10.11 | 부적합: 상한 초과 |

이 가상 LOT은 검사 5개·적합 3개·부적합 2개, 해당 치수 항목 부적합품률 40%다. 경계값 검증용 사례이며 실제 공장 품질 수준을 나타내지 않는다. 전체 제품 품질 합격이나 LOT 출하 승인을 뜻하지 않는다.

학습 순서: 규격·공차 → 측정값과 경계값 판정 → 검사 기록 → LOT별 추적 → 품질 집계. Cp/Cpk·SPC·영상 검사는 이번 기능에서 제외한다. 공정능력은 안정된 공정과 규격의 관계를 다루므로 소수 데모 데이터의 합불과 혼동하지 않는다. 보충 출처: [NIST 공정능력](https://www.itl.nist.gov/div898/handbook/pmc/section1/pmc16.htm).

## 선택 코딩 — 치수 판정 함수 하나 (15~30분)

직접 코딩은 필수가 아니다. 시작한다면 측정값·하한·상한을 받아 규격 내/외를 반환하는 작은 Java 함수가 적합하다. 프레임워크 없이 경계값과 십진수 비교를 익힐 수 있다.

기대 검사: 9.90·10.10은 적합, 9.89·10.11은 부적합, 하한>상한·누락값은 오류. 구현 시 Java BigDecimal 사용과 입력 검증을 함께 검토한다. 사용자가 원하면 이 함수만 직접 작성하고 나머지는 어시스턴트가 연결한다. 현재 완성 코드나 테스트 파일은 작성하지 않았다.
