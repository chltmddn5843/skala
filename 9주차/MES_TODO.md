## 3. 어시스턴트가 진행할 설계·구현 순서

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 기획 정책 확정 및 정의서 반영 | 대표 정상/실패 사례를 수량·상태·역할로 설명 가능 |
| 2 | 가상 데이터와 6개 화면 와이어프레임 | 각 버튼의 입력·결과·이동·실패 상태 명시 |
| 3 | OAS YML·DBML 작성 및 대조 | 모든 화면 필드/API/저장·계산 근거 대응, 문법 검증 |
| 4 | 개발 환경·기존 코드 확인 | Java/Node/DB와 기존 예제 재사용 여부 확인. 정확한 버전은 구현 시 호환성 검증 |
| 5 | DB·계정·품목 초기 데이터, 인증·권한 | 로컬 DB 실행, 역할별 로그인, 서버 권한 검사 |
| 6 | 작업지시→LOT 생산실적 구현 | 정상 등록·상태 전이, 중복 LOT·목표 초과 방지. 동시 등록 검증 |
| 7 | 검사→이력→현황 구현 | 수량·중복 검사 검증, 역할별 접근, 올바른 가중 집계 |
| 8 | AI 요약·검토 이력 연결 | 실제 호출과 데모 응답 구분, 실패 시 기존 기록 보존, 검토본 저장 |
| 9 | 통합 확인·문서 동기화 | 세 역할로 대표 시나리오 실행, API/DB/화면과 실제 동작 일치 |
| 10 | 제출 산출물 제작·발표 연습 | 개요 PDF·API YML·DB DBML·발표대본 PDF, ZIP 규칙·5분 확인 |

단계 4~9는 동작 앱 구현 경로다. 과제 제출 준비는 단계 1~3을 바탕으로 단계 10까지 진행 가능하다. 마감이 임박하면 설계 제출물을 먼저 완성한다. 배포는 필요 여부와 환경을 확인한 뒤 별도로 진행한다.

구현 위치 기본 제안: `9주차/실습자료/partflow/`. 프론트엔드는 Vue 3, 서버는 Spring Boot, DB는 PostgreSQL, AI는 Spring AI. 현시점에서는 프로젝트 생성·패키지 설치를 하지 않았다.

## 4. 구현 전 확인할 환경·자료

- 코드 작성 분담 확정: 사용자 백엔드 설계, 어시스턴트 코드·프론트 연결. 사용자 선택 코딩은 치수 판정 함수 한 개를 제안.
- AI: 수업 제공 API/계정 유무, 사용 가능한 공급자, 비용 한도. 키 원문은 대화에 붙이지 않고 로컬 환경변수로 설정한다. 정보가 없어도 AI 외 기능은 구현 가능.
- 실행 목표: 로컬 시연만 필요한지 공개 배포도 필요한지. 기본값은 로컬 시연.
- 실무 참고: 공유 가능한 작업일보·검사표·화면 예시가 있으면 파일 위치 제공. 없으면 가상 데이터로 진행하며 실제 업체 요구사항이라고 주장하지 않는다.
- 장치 요구: PC 외 태블릿·스캐너가 필요한 경우만 추가 확인.
- 설치된 Java/Node/PostgreSQL, 폴더 구조·기존 코드·버전은 어시스턴트가 확인한다. 사용자에게 미리 조사하도록 요구하지 않는다.

## 5. 학습 확인과 구현 검증

사용자가 설명해 볼 내용: 작업지시와 LOT의 차이, 생산완료와 검사완료의 차이, 검사수량을 분모로 삼는 이유, DB에 저장할 값과 계산할 값, AI가 담당하는 일.

구현 시 필요한 최소 검증: 정상 흐름, 음수·소수·초과 수량, 중복 LOT/검사, 종료된 지시 등록, 동시 실적 등록, 서버 역할 검사, 검사 0개 현황, 가중 집계, AI 실패 후 재시도. 테스트 파일은 실제 구현 시 해당 로직에 맞춰 작성한다.

현재 완료: 정의서 초안과 실행 계획. 아직 완료되지 않음: 정책 상세 확인, 와이어프레임·OAS·DBML, 앱 구현, 제출 파일, 사용자 학습 확인.
