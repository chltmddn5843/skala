
# Actuator

Spring Boot 애플리케이션의 **상태를 모니터링하고 관리하기 위한 기능**이다.

### 의존성 추가

```gradle
dependencies {
    // 애플리케이션 모니터링 endpoint를 제공합니다.
    implementation 'org.springframework.boot:spring-boot-starter-actuator'
}
```

### 주요 엔드포인트

- `/actuator/health`: 애플리케이션 정상 작동 여부
- `/actuator/info`: 애플리케이션 정보
- `/actuator/metrics`: 메모리, CPU, 요청 수 등의 지표
- `/actuator/loggers`: 로그 레벨 확인 및 변경
- `/actuator/beans`: Spring Bean 목록

```yaml
management:
  endpoints:
    web:
      exposure:
        # HTTP로 공개할 endpoint를 지정합니다.
        include: "health,info,metrics"
```

> 민감한 정보가 포함될 수 있으므로 운영 환경에서는 공개 범위와 보안 설정에 주의한다.

# Endpoint

## 개념

클라이언트가 애플리케이션의 특정 기능에 접근하기 위한 URL 진입점이다.

```text
GET /users/1
GET /actuator/health
```

## 특징

- URL과 HTTP 메서드의 조합으로 구분한다.
- 요청을 특정 Controller 메서드에 연결한다.
- JSON, HTML 등의 형태로 응답할 수 있다.

## 종류

- 애플리케이션 endpoint: 개발자가 Controller로 생성
- Actuator endpoint: Spring Boot가 모니터링 목적으로 제공

```java
@RestController
@RequestMapping("/users")
public class UserController {

    @GetMapping("/{id}")
    public String getUser(@PathVariable Long id) {
        return "사용자 ID: " + id;
    }
}
```

# Endpoint에 대한 expose

## 개념

Actuator endpoint를 HTTP 요청으로 접근할 수 있도록 **외부에 노출하는 설정**이다.

## 특징

- 기본적으로 제한된 endpoint만 노출된다.
- `include`로 노출 대상을 지정한다.
- `exclude`로 노출에서 제외한다.
- endpoint 활성화와 HTTP 노출은 서로 다른 개념이다.

## 종류

```yaml
# 일부만 노출
include: "health,info"

# 전체 노출
include: "*"

# 전체 노출 후 일부 제외
include: "*"
exclude: "beans,env"
```

## 예제

```yaml
management:
  endpoints:
    web:
      exposure:
        include: "health,info,metrics"
        exclude: "beans"
```

## 실습

서버 실행:

```bash
./gradlew bootRun
```

endpoint 확인:

```bash
curl http://localhost:8080/actuator
curl http://localhost:8080/actuator/health
curl http://localhost:8080/actuator/metrics
```

현재 프로젝트처럼 `context-path: /api`가 있다면:

```bash
curl http://localhost:8080/api/actuator/health
```

# 메트릭 Endpoint

## 개념

애플리케이션과 JVM의 성능 수치를 확인하는 Actuator endpoint다.

## 특징

- 메모리와 CPU 사용량을 확인할 수 있다.
- HTTP 요청 횟수와 처리 시간을 확인할 수 있다.
- Micrometer를 기반으로 측정한다.

## 종류

- `jvm.memory.used`: JVM 메모리 사용량
- `system.cpu.usage`: 시스템 CPU 사용률
- `process.uptime`: 애플리케이션 실행 시간
- `http.server.requests`: HTTP 요청 정보
- `jvm.threads.live`: 현재 실행 중인 스레드 수

## 예제

전체 메트릭 이름 확인:

```text
GET /actuator/metrics
```

특정 메트릭 확인:

```text
GET /actuator/metrics/jvm.memory.used
```

## 실습

```bash
curl http://localhost:8080/api/actuator/metrics
curl http://localhost:8080/api/actuator/metrics/jvm.memory.used
curl http://localhost:8080/api/actuator/metrics/http.server.requests
```

`http.server.requests`는 API를 몇 번 호출한 뒤 확인하면 측정값을 이해하기 쉽다.

# 컴포넌트 스캔

## 개념

Spring이 특정 패키지를 탐색해 관리할 클래스를 찾아 Bean으로 등록하는 기능이다.

## 특징

- `@SpringBootApplication`이 있는 패키지부터 하위 패키지를 탐색한다.
- 스캔된 객체의 생성과 연결을 Spring이 담당한다.
- 메인 클래스는 상위 패키지에 두는 것이 일반적이다.

## 종류

대표적인 스캔 대상:

- `@Component`: 일반 Spring Bean
- `@Controller`: HTML을 반환하는 Controller
- `@RestController`: JSON을 반환하는 Controller
- `@Service`: 비즈니스 로직
- `@Repository`: 데이터 접근
- `@Configuration`: 설정 클래스

## 실습

```java
@Service // 컴포넌트 스캔을 통해 Spring Bean으로 등록됩니다.
public class UserService {

    public String findUser() {
        return "홍길동";
    }
}
```

```java
@RestController
@RequestMapping("/users")
public class UserController {

    // final: 주입된 Service를 다른 객체로 재할당하지 못하게 합니다.
    private final UserService userService;

    // Spring이 등록된 UserService Bean을 주입합니다.
    public UserController(UserService userService) {
        this.userService = userService;
    }

    @GetMapping
    public String getUser() {
        return userService.findUser();
    }
}
```

## 추가) DTO

DTO는 계층 사이에서 데이터를 전달하거나 API 요청·응답 형식을 정의하는 객체다.

```java
// Long: 큰 ID를 저장하고 null도 표현할 수 있습니다.
// String: 사용자 이름과 같은 문자열을 저장합니다.
public record UserResponse(Long id, String name) {
}
```

Entity를 직접 반환하지 않고 DTO를 사용하면 내부 DB 구조와 외부 API 구조를 분리할 수 있다.

## 추가) getter와 setter

- Getter: 필드 값을 조회하는 메서드
- Setter: 필드 값을 변경하는 메서드

```java
public class User {

    private String name;

    // 현재 name 값을 반환합니다.
    public String getName() {
        return name;
    }

    // 전달받은 값으로 name을 변경합니다.
    public void setName(String name) {
        this.name = name;
    }
}
```

모든 필드에 Setter를 만들면 값이 예상하지 못한 곳에서 변경될 수 있다. 따라서 필요한 경우에만 Setter를 사용하고, 변경 목적이 분명한 메서드를 사용하는 것이 좋다.

```java
public void changeName(String newName) {
    this.name = newName;
}
```
