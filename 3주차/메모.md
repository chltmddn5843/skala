# 객체지향 프로그래밍

## 절차적 프로그래밍(PP) vs 객체 지향 프로그램 (OOP)

### 특징 차이

- 절차적 프로그래밍 : 순차, 조건 ,반복
- 객체 지향 프로그래밍 : 캡슐화, 추상화, 다형성, 상속

### 객프 특징 설명

1. 추상화 (Abstraction)

   * 개념: 복잡한 현실 세계의 대상에서 **공통적이고 핵심적인 특징**만 추출하여 모델링하는 과정
   * 백엔드 예시: 고객 관리 시스템을 만들 때 사람의 키, 몸무게, 시력 등은 제외하고, 백엔드 로직에 필요한 고객ID, 이메일, 결제수단 등 핵심 정보와 기능만 클래스로 정의하는 것입니다.
     * 자식 상속을 위해서임
2. 캡슐화 (Encapsulation)

   * 개념: 데이터(속성)와 해당 데이터를 다루는 기능(메서드)을 하나로 묶고, 외부에서의 직접적인 접근을 제한하여 보호하기
   * 백엔드 예시: 사용자의 비밀번호 변수를 외부에서 직접 수정하지 못하게 private으로 막아두고, 검증 로직을 거치는 메서드(e.g., changePassword())를 통해서만 변경할 수 있도록 안전장치를 마련합니다.
3. 상속 (Inheritance)

   * 개념: 상위 클래스(부모)의 자원(필드, 메서드)을 하위 클래스(자식)가 물려받아 재사용하거나 확장하는 것입니다.
   * 백엔드 예시: 공통 유저 클래스(User)를 정의하고, 이를 상속받아 일반 회원(Member)과 관리자(Admin) 클래스를 만들어 중복 코드를 극적으로 줄입니다.
4. 다형성 (Polymorphism) ★★★ (Spring의 핵심)

   - 개념: 하나의 타입이나 메서드가 상황에 따라 여러 가지 다양한 형태/동작으로 변신하는 성질입니다. (오버라이딩, 역할과 구현의 분리)
   - 백엔드 예시: 결제(Payment)라는 역할(인터페이스)을 정의해 두면, 실제 구현체가 카카오페이결제, 신용카드결제, 토스페이결제 등 무엇이 들어오든 동일한 인터페이스로 처리할 수 있습니다.

## SOLID 원칙

## 📌 SOLID 5대 원칙 요약

1. SRP (단일 책임 원칙, Single Responsibility Principle)

   * 개념: 하나의 클래스는 단 하나의 책임(변경 이유)만 가져야 한다.
   * 백엔드 예시: Controller(요청 처리), Service(비즈니스 로직), Repository(DB 접근)로 계층을 분리하여 구현한다.
2. OCP (개방-폐쇄 원칙, Open/Closed Principle)

   * 개념: 기능 확장에는 열려(Open) 있어야 하고, 기존 코드 수정에는 닫혀(Closed) 있어야 한다.
   * 백엔드 예시: Payment 인터페이스를 정의한 후 카카오페이, 네이버페이 등 결제 수단을 추가할 때 기존 로직 변경 없이 클래스만 추가한다.
3. LSP (리스코프 치환 원칙, Liskov Substitution Principle)

   * 개념: 하위 타입(자식 클래스)은 언제나 상위 타입(부모 인터페이스)을 대체할 수 있어야 한다.
   * 백엔드 예시: 인터페이스에 정의된 동작 약속(규약)을 자식 구현체가 깨뜨리지 않고 올바르게 동작해야 한다.
4. ISP (인터페이스 분리 원칙, Interface Segregation Principle)

   * 개념: 사용하지 않는 메서드에 의존하지 않도록 인터페이스를 작고 명확하게 분리해야 한다.
   * 백엔드 예시: 하나의 거대한 인터페이스보다 기능별로 쪼개진 여러 인터페이스를 작성하여 불필요한 메서드 구현을 방지한다.
5. DIP (의존역전 원칙, Dependency Inversion Principle) -???

   - 개념: 구체적인 구현 클래스가 아닌, 추상화(인터페이스)에 의존해야 한다.
   - 백엔드 예시: OrderService가 특정 결제 구현체 클래스를 직접 생성하지 않고 PaymentClient 인터페이스에만 의존하며, Spring이 외부에서 객체를 주입(DI)해준다.

# 2일차 Configuration과Profile 관리

> App 실행 시 필요한 환경 정보 (포트, DB, API )를 코드가 아닌 외부 파일 또는 환경변수로 분리해 관리하는 것을 의미함
> 즉, 코드를 수정하지 않고 **환경에 따라** 설정만 바뀌어 APP 실행 가능토록 함

## 개발된 이유

> 기존 방식에서는 개발 운영마다 환경이 달라서 DB 세팅하는 방법이 다름
> 설정 정보를 코드 밖(yml, 환경 변수)으로 추출해두면 설정 따라 받으면 됨

## 어노테이션 종류

### `@ConfigurationProperties`

- 기능: 공통 접두사를 가진 여러 설정값을 하나의 객체로 묶어 주입
- 목적: 설정값을 타입 안전하고 체계적으로 관리
- 특징:
  - 설정이 많을 때 적합
  - YAML의 계층 구조를 객체로 표현 가능
  - 타입 변환과 유효성 검증 지원
  - Spring Bean으로 등록해야 사용 가능

```yaml
app:
  name: my-service
  timeout: 30
```

```java
@ConfigurationProperties(prefix = "app")
public record AppProperties(
    String name,
    int timeout
) {}
```

등록 방법:

```java
@ConfigurationPropertiesScan
@SpringBootApplication
public class Application {
}
```

---

### `@Value`

- 기능: 설정값 하나를 특정 필드나 생성자 매개변수에 주입
- 목적: 소수의 간단한 설정값을 개별적으로 사용
- 특징:
  - `${키:기본값}` 형태로 사용
  - 기본값 지정 가능
  - SpEL 표현식 사용 가능
  - 설정값이 많아지면 관리하기 어려움
  - `@ConfigurationProperties`보다 타입 안전성과 구조화가 부족함

```java
@Value("${app.name:default-app}")
private String appName;
```

> `@Value`는 여러 설정을 하나의 객체로 묶는 기능이 아니라, 설정값을 **개별적으로 주입**하는 기능이다.

## 검증 어노테이션

- 개념: 입력값이나 설정값이 지정된 규칙에 맞는지 확인하는 기능
- 목적: 잘못된 설정으로 애플리케이션이 실행되는 것을 방지
- 의존성:

```gradle
implementation 'org.springframework.boot:spring-boot-starter-validation'
```

`@ConfigurationProperties`를 검증하려면 `@Validated`를 추가한다.

```java
@Validated
@ConfigurationProperties(prefix = "mail")
public record MailProperties(
    @NotBlank String host,
    @Min(1) @Max(65535) int port,
    @Email String sender
) {}
```

### 주요 검증 어노테이션

- `@NotNull`: 값이 `null`이면 안 됨
- `@NotBlank`: 문자열이 `null`, 빈 문자열 또는 공백이면 안 됨
- `@NotEmpty`: 문자열이나 컬렉션이 `null` 또는 비어 있으면 안 됨
- `@Size`: 문자열·컬렉션 등의 크기 제한
- `@Email`: 이메일 형식 검사
- `@Pattern`: 정규 표현식 검사
- `@Min`, `@Max`: 숫자의 최솟값·최댓값 검사
- `@Positive`: 양수인지 검사

> 어노테이션 이름은 대소문자를 구분하므로 `@Notnull`이 아니라 `@NotNull`이다.

## Profile

### 개념 : dev,test,prod등 환경별로 다른 설정을 자동으로 적용하는 기능

> 즉 현재 실행 중인 프로파일이 무엇인지에 따라서 다른 DB 설정, 다른 서버 포트등 서로 다른 설정이 가능함


### 특징

- 환경 분리해서 (개발용포트, 테스트용 포트, 운영 포트 분리 가능)
- spring.profiles.active 값만 변경하면 환경 전환 가능
- 자동 병합: 공통 설정과 환경별 설정을 자동으로 병합함

### 구성 : application-.yml

- 사용방법 : gradlew bootRun --args='--spring.profiles.active=prod'

> src
> └── main
> └── resources
> ├── application.yml       # 모든 환경의 공통 설정
> ├── application-dev.yml   # 개발 환경
> ├── application-test.yml  # 테스트 환경
> └── application-prod.yml  # 운영 환경

## Spring MVC

> Spring MVC는 **웹 요청을 Controller가 처리하고 결과를 View 또는 JSON으로 반환하는 Spring의 웹 프레임워크**이다. MVC는 Model, View, Controller의 약자다.

### 특징

- MVC 패턴으로 역할을 분리
- 어노테이션 기반 요청 처리
- URL과 HTTP 메서드를 Controller에 매핑
- 요청 데이터 자동 변환 및 검증 지원
- 예외를 공통으로 처리할 수 있

### 주요 컴포넌트

```text
DispatcherServlet
├── HandlerMapping
├── HandlerAdapter
├── Controller
├── Service
├── Model
├── ViewResolver
└── View
```

- `DispatcherServlet`: 모든 요청을 가장 먼저 받는 중앙 컨트롤러
- `HandlerMapping`: 요청을 처리할 Controller 메서드를 검색
- `HandlerAdapter`: 검색된 Controller 메서드를 실행
- `Controller`: 요청을 받고 응답을 결정
- `Model`: View에 전달할 데이터
- `ViewResolver`: View 이름에 해당하는 실제 화면 파일 검색
- `View`: HTML 화면 생성
- `HttpMessageConverter`: 객체와 JSON을 서로 변환
- `Service`: 비즈니스 로직 처리
- `Repository`: 데이터베이스 접근

### 주요 처리 흐름

### HTML을 반환하는 경우

```text
클라이언트 요청
    ↓
DispatcherServlet
    ↓
HandlerMapping
    ↓
HandlerAdapter
    ↓
Controller → Service → Repository
    ↓
Model + View 이름
    ↓
ViewResolver
    ↓
View 렌더링
    ↓
HTML 응답
```

### JSON을 반환하는 경우

```text
클라이언트 요청
    ↓
DispatcherServlet
    ↓
Controller
    ↓
Service → Repository
    ↓
반환 객체
    ↓
HttpMessageConverter
    ↓
JSON 응답
```

### 의존성 설치

### Gradle

```gradle
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web'
}
```

### Maven

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

`spring-boot-starter-web`에는 Spring MVC, 내장 Tomcat, JSON 변환을 위한 Jackson 등이 포함된다.

### 기본 사용 예시

```java
@RestController
@RequestMapping("/users")
public class UserController {

    private final UserService userService;

    public UserController(UserService userService) {
        this.userService = userService;
    }

    @GetMapping("/{id}")
    public UserResponse getUser(@PathVariable Long id) {
        return userService.findById(id);
    }
}
```

```java
@Service
public class UserService {

    public UserResponse findById(Long id) {
        return new UserResponse(id, "홍길동");
    }
}
```

```java
public record UserResponse(
    Long id,
    String name
) {}
```

요청:

```http
GET /users/1
```

응답:

```json
{
  "id": 1,
  "name": "홍길동"
}
```

핵심은 **`DispatcherServlet`이 요청을 받고 적절한 Controller를 실행한 뒤, 결과를 HTML이나 JSON으로 변환해 응답한다는 것**이다.

Actuator

Spring Boot 애플리케이션의 **상태를 모니터링하고 관리하기 위한 기능**이다.

### 의존성 추가

```gradle
implementation 'org.springframework.boot:spring-boot-starter-actuator'
```

### 주요 엔드포인트

- `/actuator/health`: 애플리케이션 정상 작동 여부
- `/actuator/info`: 애플리케이션 정보
- `/actuator/metrics`: 메모리, CPU, 요청 수 등의 지표
- `/actuator/loggers`: 로그 레벨 확인 및 변경
- `/actuator/beans`: 등록된 Bean 목록

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health, info, metrics
```

> 민감한 정보가 포함될 수 있으므로 운영 환경에서는 공개 범위와 보안 설정에 주의한다.

### `DispatcherServlet`이란?

Spring MVC의 **모든 HTTP 요청을 가장 먼저 받아 적절한 Controller로 전달하는 중앙 서블릿**이다. Front Controller라고도 한다.

```text
클라이언트 요청
    ↓
DispatcherServlet
    ↓
HandlerMapping으로 Controller 검색
    ↓
HandlerAdapter로 Controller 실행
    ↓
HTML 또는 JSON 응답
```

Spring Boot에서는 `DispatcherServlet`이 자동으로 등록되므로 일반적으로 직접 설정할 필요가 없다.

## Controller

HTTP 요청을 받아 요청값을 해석하고, Service를 호출한 뒤 결과를 반환하는 계층이다.

- `@Controller`: 주로 View 이름을 반환
- `@RestController`: 객체를 JSON으로 반환
- `@RestController` = `@Controller` + `@ResponseBody`

```java
@RestController
@RequestMapping("/users")
public class UserController {
}
```

### `@RequestMapping`

Controller나 메서드에 **공통 URL과 HTTP 메서드를 연결**한다.

```java
@RequestMapping("/users")
```

```java
@RequestMapping(value = "/list", method = RequestMethod.GET)
public List<User> getUsers() {
    return users;
}
```

일반적으로 HTTP 메서드별 전용 어노테이션을 더 많이 사용한다.

- `@GetMapping`: 조회
- `@PostMapping`: 생성
- `@PutMapping`: 전체 수정
- `@PatchMapping`: 일부 수정
- `@DeleteMapping`: 삭제

### `@RequestParam`

URL의 **쿼리 파라미터** 또는 폼 데이터를 매개변수로 받는다.

```java
@GetMapping
public String search(
    @RequestParam String keyword,
    @RequestParam(defaultValue = "1") int page
) {
    return keyword + ", " + page;
}
```

요청 예시:

```http
GET /users?keyword=kim&page=2
```

주요 옵션:

- `required`: 필수 여부이며 기본값은 `true`
- `defaultValue`: 값이 없을 때 사용할 기본값
- `name` 또는 `value`: 요청 파라미터 이름 지정

```java
@RequestParam(name = "keyword", required = false)
String keyword
```

### `@PathVariable`

URL 경로에 포함된 값을 매개변수로 받는다. 주로 특정 자원을 식별할 때 사용한다.

```java
@GetMapping("/{id}")
public String getUser(@PathVariable Long id) {
    return "사용자 번호: " + id;
}
```

요청 예시:

```http
GET /users/10
```

이때 `id`에는 `10`이 전달된다.

### 차이점

```text
@RequestParam  → /users?name=kim   검색·필터·정렬·페이지
@PathVariable → /users/10         특정 자원 식별
```
