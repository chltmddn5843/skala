
## localhost 접속 시 원하는 응답이 나오지 않는 문제

- 현상 : Spring Boot 서버는 실행되었지만 `http://localhost:8080`에 접속했을 때 오류 페이지가 나오거나 원하는 JSON 응답이 나타나지 않았다.
- 원인 : `/` 경로를 처리하는 Controller가 없었으며, 애플리케이션에 `server.servlet.context-path: /api`가 설정되어 있어 실제 요청 주소 앞에 `/api`가 필요했다.
- 해결 : Controller의 `@RequestMapping`, `@GetMapping` 경로와 `context-path`를 조합해 실제 endpoint로 접속한다. 예를 들어 설정 조회 API는 `http://localhost:8080/api/config`로 호출한다.

## Actuator endpoint가 노출되지 않는 문제

- 현상 : Actuator 의존성을 추가했지만 `/actuator/env`, `/actuator/beans` 등의 endpoint에 접근할 수 없었다.
- 원인 : Actuator 의존성 추가와 HTTP 노출은 별개의 설정이다. 현재 설정은 기본 접근을 `none`으로 지정하고 `health`, `info`, `metrics`만 `read-only`로 허용했으며, HTTP 노출 대상도 이 세 endpoint로 제한했다. 또한 `/api` context-path가 적용되어 있었다.
- 해결 : 필요한 endpoint를 `management.endpoint`에서 활성화하고 `management.endpoints.web.exposure.include`에 추가한다. 현재 설정에서는 `http://localhost:8080/api/actuator/health`처럼 접근한다. 전체 노출을 의미하는 `"*"`와 `env.show-values: always`는 민감정보가 보일 수 있으므로 로컬 실습에서만 사용한다.

## VS Code에서 Java 프로젝트를 열었을 때 메모리 사용량이 증가하는 문제

- 현상 : VS Code에 `Building`, `Validating Gradle wrapper checksum`, `Synchronizing Gradle build`가 반복해서 표시되면서 컴퓨터가 느려졌다.
- 원인 : Java 자체의 오류가 아니라 여러 Gradle 프로젝트가 들어 있는 상위 폴더를 열어 VS Code가 프로젝트들을 동시에 검색하고 동기화했다. 그 결과 Gradle 8.14.3, 9.5.1, 9.6.1 Daemon과 Java 및 Spring Boot 언어 서버가 함께 실행되었다.
- 해결 : VS Code에서 상위 폴더 대신 현재 작업할 `configuration-profile-sample` 폴더만 연다. 사용하지 않는 Gradle Daemon은 `./gradlew --stop`으로 종료하고, 필요하면 명령 팔레트에서 `Java: Clean Java Language Server Workspace`를 실행한다. `[Done]` 메시지는 오류가 아니라 작업이 정상 완료되었다는 의미다.

## Complie Error JAVA

- 현상 : ./gradlew 명령어로 자바 프로젝트 빌드/컴파일 중 :compileJava 작업에서 실패 발생.
  - Could not find org.springframework.boot:spring-boot-starter-webmvc:. 메시지가 출력되며 의존성 모듈을 로드하지 못함.

2. 원인 : [버전 정보 누락] 의존성 이름 끝의 콜론(:) 뒤에 명시되어야 할 버전 번호가 빈값으로 처리됨.
3. 의존성 이름 오류: Spring Boot의 웹 관련 표준 라이브러리 명칭은 spring-boot-starter-web인데, 존재하지 않거나 오타가 난 spring-boot-starter-webmvc로 선언됨.
4. 해결
   ① build.gradle 파일 수정
   dependencies 블록 안의 해당 라이브러리명을 Spring Boot 표준 명칭으로 변경합니다.

## applicatiopn.properties 와 application.yml은 세팅 방법이 다르다.

### properties

spring.application.name=demo
server.port=8081

management.endpoints.web.exposure.include=beans, health, info, metrics, env, httptrace
management.endpoint.health.show-details=always

### yml

spring:
  application:
    name: demo

server:
  port: 8081

management:
  endpoints:
    web:
      exposure:
        include: "beans, health, info, metrics, env, httptrace"
        # show-details는 health 엔드포인트 하위 설정이어야 합니다
  endpoint:
    health:
      show-details: always
