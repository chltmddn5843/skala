# 서브노트

### 인사이트

> 초심 : ai 서비스를 구현할 수 있는 인재가 되기 위함이었음

1. 프로젝트 운영 시, 새로운 서비스를 개발해야할 때 추가 리소스를 관리,운용하는 방법론을 배운다.
2. 이해관계자의 가치를 유지한 채, 표면적으로 서비스를 변화시켜야함 -> 애자일 방법론

### 현업에서는..

1. 기존 업무에 ai 서비스를 붙이고 싶어함
2. 새로운 서비스를 만드는 것이 아닌 기존 업무 자체 붙이는 것임

### 애자일 방법론

- 목표 : 조직의 가치와 철학을 유지하는 것임
- 반복적이고 짧은 Sprint 단위를 반복하며 점진적으로 개발함
- 현장의 요구 사항을 반영하지 못해서 스프린트만 반복하는 경우가 있기에 꼭 피드백하며 다음 스프린트에 반영하는 식으로 발전시킴
- 진행사항을 가시화하는 것이 중요함 짧은 단위로 달리고 점검하는 만큼 큰 라인을 처음부터 설계하는 것이 아님 중간중간 설정해야함
- 중요 포인트 중 하나는 : 전체 츠로그램이 얽혀있는 것이 아닌 독립적으로 구성하여 기능 하나를 고칠 때 다른 서비스에 영향 주지 말자

### 이해관계자 설정하는 것 중요

- 이분들도 gpt, 클로드 사용 가능함 그만큼 나도 포인트를 잘 잡아서 정리해야함
- 10년 동안 쌓은 신뢰는 ai로 바로 잃어버릴 수 있다.

### Eureka가 무엇인가?

**마이크로서비스 주소록으로 서비스가 재시작되어 IP나 포트가 바뀌어도 주소를 하드코딩하지 않아도됨**

* 다른 서비스가 IP/포트를 직접 몰라도 서비스 이름으로 찾아 호출
* API Gateway도 Eureka를 통해 `user-service`, `course-service` 등을 찾음
