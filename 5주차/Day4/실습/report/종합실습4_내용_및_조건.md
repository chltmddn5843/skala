# 종합실습 4 - E-Commerce 매출 분석 및 정리

## 1. 실습 목적

E-Commerce 데이터팀의 주니어 엔지니어로서 구매·재무 등 다른 팀이 요청한 자료를 SQL로 추출하고, 결과와 근거를 전달하는 연습이다.

핵심은 단순히 쿼리를 작성하는 것이 아니라 다음 과정을 재현하는 데 있다.

1. 요청 문장을 데이터 조건으로 변환한다.
2. 매출·주문·고객의 집계 단위를 명확히 정한다.
3. 랜덤 데이터에서도 재현 가능한 분석 로직을 만든다.
4. 튜닝 전후의 쿼리, 실행 결과, 실행계획을 비교한다.
5. 요청 부서가 이해할 수 있는 형태로 결과와 해석을 정리한다.

## 2. 실행 환경과 순서

- DBMS: PostgreSQL 14 이상
- 작업 스키마: `ecom`
- 사용 확장: `citext`, `btree_gist`

실행 순서:

1. `종합실습4_ecom_schema_postgres_테이블생성.sql`
2. `종합실습4_ecom_seed_postgres_데이터입력.sql`
3. 데이터 건수와 주요 제약조건 확인
4. Q1~Q11 분석 쿼리 실행

시드 스크립트는 기존 데이터를 `TRUNCATE ... RESTART IDENTITY CASCADE`로 초기화하므로 재실행 전에 주의한다. 데이터가 무작위로 생성되기 때문에 실행할 때마다 금액과 건수는 달라질 수 있다.

## 3. 주요 테이블

| 영역 | 테이블 | 용도 |
|---|---|---|
| 고객 | `customers`, `addresses`, `country` | 고객·주소·국가 정보 |
| 상품 | `products`, `categories` | 상품과 계층형 카테고리 |
| 가격 | `product_prices` | SCD2 방식 가격 이력 |
| 주문 | `orders`, `order_items` | 주문 헤더와 상품별 매출 |
| 결제·배송 | `payments`, `shipments` | 결제 및 배송 정보 |
| 재고 | `inventory` | 현재 재고와 재주문 임계치 |
| 평가 | `reviews` | 상품별 평점과 리뷰 |
| 공급 | `suppliers`, `product_suppliers` | 상품 공급사 정보 |

## 4. 공통 분석 기준

- 실제 매출 주문 상태: `paid`, `shipped`, `delivered`
- 실제 매출에서 제외할 상태: `created`, `cancelled`, `refunded`
- 매출액: `order_items.line_total`
- 상품 행 매출: `unit_price * qty - discount`
- 주문 시각: `orders.order_ts`
- 주문 수: 상품 행 수가 아닌 `COUNT(DISTINCT order_id)`
- 채널: `web`, `mobile`, `marketplace`
- 재고 부족: `qty_on_hand < reorder_point`
- 가격 이력 유효 구간: `[valid_from, valid_to)`

요청 결과에는 조회 기준 시각, 대상 기간, 포함한 주문 상태, 금액 단위와 반올림 기준을 함께 기록한다.

## 5. 실습 문제와 힌트

### Q1. 최근 한 달 실제 총매출

- 조건: `order_status IN ('paid','shipped','delivered')`
- 기간: `order_ts >= now() - interval '1 month'`
- 계산: `order_items.line_total` 합계

### Q2. 월별 주문 수·매출·평균 주문 금액(AOV)

- `date_trunc('month', order_ts)`로 월 그룹 생성
- 주문 수는 `COUNT(DISTINCT order_id)` 사용
- AOV는 월 매출을 월 주문 수로 나누어 계산

### Q3. 최근 90일 카테고리 매출 Top 10

- 조인: `order_items → products → categories`
- 최근 90일 및 실제 매출 상태 필터 적용
- 카테고리별 매출 합계 내림차순 상위 10개

### Q4. 상품별 누적 매출 순위 Top 20

- 상품별 매출을 먼저 집계
- 집계 결과에 `RANK() OVER (ORDER BY 매출 DESC)` 적용
- 순위 기준 상위 20개 추출

### Q5. 고객 RFM 분석

- Recency: 고객별 `MAX(order_ts)`를 기준일과 비교
- Frequency: 고객별 실제 구매 주문 수
- Monetary: 고객별 `SUM(line_total)`
- 주문과 주문상품의 1:N 조인 때문에 빈도는 중복 주문을 제거해야 한다.

### Q6. 첫 구매 후 30일 이내 재구매율

- 고객별 첫 구매일: `MIN(order_ts)`
- 첫 구매보다 늦고 첫 구매일로부터 30일 이내인 추가 주문 확인
- 재구매율: 30일 내 재구매 고객 수 / 첫 구매 고객 수

### Q7. 재고 부족 위험 상품

- 조건: `inventory.qty_on_hand < inventory.reorder_point`
- 상품 정보와 조인해 상품명, 현재고, 임계치, 부족 수량을 제공

### Q8. 리뷰 기반 효자상품

- 리뷰를 상품별 그룹화
- 조건: `HAVING AVG(rating) >= 4.5 AND COUNT(*) >= 50`
- 시드 파일 주석의 60개는 데이터 보장 수준이며 문제 판정 기준은 50개다.

### Q9. 쿠폰 사용 영향

- `coupon_code IS NOT NULL` 여부로 구분
- 먼저 주문별 금액을 집계한 뒤 그룹별 평균 주문 금액 비교
- 상품 행을 바로 평균 내면 주문당 평균이 아닌 주문상품 행 평균이 되므로 주의한다.

### Q10. 상위 1% 고객의 최근 60일 매출

- 전체 고객 누적매출로 상위 1% 고객 선정
- 전체 고객 3,000명 기준 목표 인원은 30명
- 선정된 고객에 대해 최근 60일 실제 매출만 별도로 합산
- 동점 처리 방식에 따라 인원이 달라질 수 있으므로 정확히 30명이 필요하면 정렬 후 `LIMIT 30`을 사용한다.

### Q11. 안전한 나눗셈 함수

두 함수의 이름과 0 처리 결과가 다르므로 혼용하지 않는다.

| 함수 | 위치 | 분모가 0일 때 |
|---|---|---|
| `ecom.f_safe_div(numer, denom)` | 스키마 파일 | `0` 반환 |
| `ecom.safe_div(n, d)` | 시드 파일 | `NULL` 반환 |

평균값에서 데이터 없음과 실제 0을 구분하려면 `ecom.safe_div()`의 `NULL` 반환이 더 적합하다. 사용 전 `SELECT`로 0, `NULL`, 정상 분모를 각각 검증한다.

- 주문별 금액을 먼저 계산해야 하는 분석에서 집계 순서가 맞는가?
- 랜덤 데이터의 결과값이 아니라 로직과 기준을 설명했는가?
- 실행 결과 캡처에 쿼리, 결과, 실행 시각이 식별되는가?
